计算机网络实验：Wireshark 抓包

发表于2026-04-13|更新于2026-11-07|计算机网络
|浏览量:

实验要求

实验目的

学习安装、使用协议分析软件，掌握基本的数据报捕获、过滤和协议分析技巧，能对抓取的数据包进行分析。

实验内容与任务

  • 任务 3.1（Wireshark 的使用）：安装配置网络嗅探器；设置抓包过滤器和显示过滤器，抓取一个 HTTP 会话过程所传输的包，观察包结构和格式，分析各字段语义，以图形化方式显示该会话过程；利用过滤器抓取/显示一个完整的 POP3 会话，截图并说明会话中双方交换的各报文含义；总结网络嗅探器的功能。
  • 任务 3.2（HTTP 协议的认知与分析）：掌握浏览网页时 HTTP 协议的工作过程；抓取一个 HTTP 会话所传输的报文，分析报文结构、格式及内容；观察完整 HTTP 会话各阶段的请求/响应操作；重建 HTTP 会话并说明各报文含义；回答实验指导中的 10 个问题。
  • 任务 3.3（TCP 协议的认知与分析）：掌握 TCP 协议的语法、语义和时序；抓取 TCP 会话报文并分析结构；捕获 TCP 三次握手建立连接的完整数据包，分析时序关系（注意源/目的 IP 与端口的匹配）；分析 SYN、ACK、Sequence number 之间的关系；说明报文序号的单位、作用以及不同会话的起始序号规律。

实验环境：Windows 操作系统；Internet 连接；抓包软件 Wireshark。

实验过程与结果

3.1 网络协议分析软件 Wireshark 的使用

在进入wireshark之后，可以着手开始实验，进到主页可以看到有多种接口可以选，由于我使用的是宿舍的以太网，有显示波动，我就选了相对应的接口，进入接口抓包

进入抓包后可以看到不断地有资源、地址进来，这是wireshark在以太网接口不断地抓取流量

按下左上角地停止按钮（红色），即可停止抓包

在每一行其实就是编号，时间戳，源地址，目标地址，协议，长度还有一些数据包信息，在过滤器的使用便是要对这些进行过滤，将不需要的包过滤、整理，达到精准读取

像这些信息就是不同的层次，比如说FRAME物理层，点击可以看到物理层的详细信息

对于过滤器来说，有多种过滤的命令来进行学习

根据上述实验内容回答以下问题：

（1）你的浏览器运行的 HTTP 版本是 1.0 还是 1.1？服务器端的 HTTP 版本是什么？

浏览器：HTTP/1.1；服务器：HTTP/1.1

（2）你的浏览器指出它所能够接受的语言是什么？

未显示，应该是默认

（3）你的计算机的 IP 地址是什么？你所浏览的网站服务器的 IP 地址是什么？

计算机 IP：172.29.44.218；服务器 IP：120.233.51.142

（4）服务器返回给浏览器的状态码（Status code）是什么？代表了什么含义？

状态码：200。含义：OK（请求成功）——服务器成功处理了请求，并返回了请求的资源

（5）你所访问的 HTML 文件在服务器上最后的修改时间是什么？

Last-Modified: Tue, 18 Feb 2025 22:45:32 GMT，即最后修改时间为 2025 年 2 月 18 日 22:45:32 GMT

（6）浏览器发出了多少个 HTTP GET 请求？

一个

（7）观察浏览器中发出的第 1 个 HTTP GET 请求，其中是否含有 “IF-MODIFIED-SINCE” 这一行？

否，不含 If-Modified-Since 这一行

（8）观察服务器响应报文的内容，服务器是否显式地返回了所请求的文件内容？你如何解释这种现象？

是，服务器显式返回了所请求的文件内容（JPEG 图片，2879 字节）。解释：

  • 状态码 200 表示成功，服务器必须返回实体内容
  • 返回的是二进制图片数据，在 ASCII 显示模式下显示为乱码（这是正常的）
  • 如果状态码是 304（Not Modified），则不会返回内容

（9）HTTP 客户端从服务器端获取网页对象使用的命令是什么？该命令每次能获取一个完整的网页吗？

GET。一个 GET 命令可以获取一个资源（如一张图片、一个 HTML 文件），但一个完整网页通常需要多个 GET 请求（HTML + CSS + JS + 图片等）

（10）浏览一个网页需要进行几次 TCP 连接？连接次数与什么有关？

至少 1 个 TCP 连接（HTTP/1.1 的 Keep-Alive 特性）

SYN/ACK/Seq关系

核心规律：

  1. SYN消耗1个序号：Seq从0开始，下一个Seq=1

  2. ACK = 对方Seq + 1：确认已收到的序号

  3. 双向序号独立：客户端和服务器各自从0开始（相对）

序号机制

单位：字节

作用：有序传输、丢包检测、可靠重传、去重

初始序号：随机生成，不同会话不同

报文组成格式：

拿我刚刚展示的SYN包为例

根据捕获的TCP数据报，TCP报文由以下部分组成：

一、TCP头部（固定20字节 + 可选选项）

字段 长度 说明
源端口 16位 标识发送方应用进程，如 50585
目的端口 16位 标识接收方服务，如 80(HTTP)
序列号 32位 数据字节流位置，如 0、1
确认号 32位 期望收到的下一个序号
数据偏移 4位 头部长度，单位 4 字节
保留 6位 保留字段，必须为 0
标志位 6位 SYN/ACK/PSH/FIN/RST/URG
窗口大小 16位 接收缓冲区大小，流量控制
校验和 16位 差错检测
紧急指针 16位 紧急数据位置
选项 0-40位 MSS、窗口扩大等可选参数

二、TCP数据（可变长度）

承载应用层数据

SYN/FIN包数据长度为0

数据包长度为实际传输字节数（如329字节）

三、抓包验证

Frame 11：头部32字节（含12字节选项）+ 数据0字节 = 32字节

Frame 14：头部20字节（无选项）+ 数据329字节 = 349字节

讨论与总结

  1. 本次实验成功使用Wireshark捕获并分析了HTTP、POP3和TCP协议的实际通信过程

  2. 发现现代网站普遍采用HTTPS加密，明文HTTP已较少使用

  3. POP3协议分析中，观察到用户名和密码以明文传输，深刻认识到明文协议通过TCP三次握手的抓包分析，直观理解了Seq、Ack和SYN/ACK标志的协调工作机制。

  4. Wireshark的显示过滤器和抓包过滤器功能强大，语法有所不同

  5. Follow TCP Stream功能极大简化了会话重组分析，是理解应用层协议交互的利器

  6. 实验表明HTTP/1.1的Keep-Alive特性有效减少了TCP连接建立开销，提升了网页加载效率。

  7. 随机初始序号（ISN）机制是TCP安全设计的重要体现，可防止序列号预测攻击。

  8. 窗口大小和选项协商展示了TCP的流量控制和性能优化能力，适应不同网络环境。

  9. 建议后续实验增加HTTPS/TLS抓包分析，使用中间人代理解密加密流量，拓展安全研究能力。

  10. 可进一步探索HTTP/2和HTTP/3协议，观察多路复用和QUIC协议对性能的提升效果。

意见与建议

  1. 希望增加邮件客户端配置的图文教程，详细说明Foxmail、Outlook等工具的POP3设置步骤，减少学生在环境搭建上的时间消耗。

  2. 建议补充HTTPS/TLS协议分析内容，引入中间人代理工具让我们理解现代加密通信的抓包方法，提升实验的实用性和前沿性。

  3. 建议优化Wireshark过滤器的讲解顺序，先演示抓包后过滤再讲抓包前过滤，降低理解门槛。
